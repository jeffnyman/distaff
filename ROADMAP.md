# Distaff roadmap

What is done, what comes next, and where each piece comes from. Source references are to the
ScummVM checkout at `../_loom/scummvm/engines/scumm`.

## Design

ScummVM builds Loom's engines as a chain of subclasses: the EGA release runs on
`ScummEngine_v3old : v3 : v4 : v5 : ScummEngine`, the FM Towns release on `ScummEngine_v3` (the
same chain, without `v3old`), and the VGA CD release on `ScummEngine_v4`. Much of what Loom runs
on lives in the V5 and base classes, mixed with code for later games (iMUSE, HE, SMUSH, AKOS).
Distaff does not port that chain. It has one flat engine with the release as data, and it takes
from each ScummVM function only the branches that `GID_LOOM` and versions 3 and 4 reach. ScummVM
has about 200 `GID_LOOM` special cases; each is ported or ruled out on purpose, not by accident.

The three releases split the work like this:

| | EGA (v3old) | VGA CD (v4) | FM Towns (v3, `GF_OLD256`) |
|---|---|---|---|
| Engine class | `ScummEngine_v3old` | `ScummEngine_v4` | `ScummEngine_v3` |
| Files | `NN.LFL`, XOR 0xFF | `000.LFL`, `90x.LFL`, `DISK01.LEC` XOR 0x69 | `NN.LFL`, not encoded |
| Resource headers | 4 bytes (`GF_OLD_BUNDLE`) | 6 bytes (`GF_SMALL_HEADER`) | 6 bytes |
| Index | `ScummEngine_v3old::readIndexFile` | `ScummEngine_v4::readIndexFile` | `ScummEngine_v3::readIndexFile` |
| Colours | 16 (`GF_16COLOR`, `drawStripEGA`) | 256 | 256, with the Towns' text layer (`gfx_towns.cpp`) |
| Scripts | v5 opcodes with v4 and v3 changes | v5 opcodes with v4 changes | as EGA |
| Sound | PC speaker and PCjr (`Player_V2`), AdLib (`Player_AD`), MT-32 (iMUSE) | CD audio (`soundcd.cpp`) | `Player_Towns_v1` and CD audio |

The EGA release comes first: it is the one people think of as Loom, and it has the full
dialogue the CD release cut. VGA follows, because it shares the most with EGA once the 256-colour
drawing and the DISK01.LEC bundle are in. FM Towns comes last.

Every phase ends with a headless check: a screenshot of a known room, or a scripted run of
clicks that reaches a known state.

## Done

- Solution layout, build settings and the host contract (from Daventry by way of Maniacal).
- Detection: ScummVM's 34 Loom MD5 rows (generated by `tools/port_md5_table.py`), the
  variant-to-version table of `detection_tables.h` and `metaengine.cpp`, and identification by
  `00.LFL` or `000.LFL`. The English DOS EGA, DOS VGA CD and FM Towns releases are identified.

## EGA

### Phase 1: resources (done)

In `Distaff.Scumm.Resources` and `Rooms`:

- `file.cpp`, `resource.cpp` (`getEncByte`, `loadResource`), `resource_v3.cpp`,
  `resource_v4.cpp` (`readGlobalObjects`): the XOR-0xFF `.LFL` files (`LflFile`), the index
  (`ResourceIndex`: magic 0x0100, 1000 global objects with their classes, owners and states, and
  the room, costume, script and sound directories), and loading a resource by the size word of
  its 4-byte header (`ResourceLoader`). Global scripts' code starts after the header.
- `room.cpp`, `object.cpp`, `boxes.cpp`, `script.cpp` (reading): the room header (`Room`), the
  object code blocks with their names and verb tables (`RoomObject`), the walkboxes and the box
  matrix as stored (`WalkBoxes`), the entry and exit scripts and the local scripts.
- `sound.cpp` (`readSoundResourceSmallHeader`): each sound's speaker and AdLib blocks
  (`SoundResource`).
- `resource_v3.cpp` (`loadCharset`): the charset in `99.LFL`, which is not encoded.
- Player: `--room N` lists a room's header, scripts, walkboxes and objects.
- Checked against the EGA release: every room file is an exact chain of resources; all 76 rooms
  parse. The index entries that point at no real resource are counted and pinned: 11 rooms whose
  files are not on the disks, 2 costumes stored in them, and 11 costumes, 2 scripts and sound 24
  whose offsets run past their files or into another resource.
- The release carries the Roland Upgrade: `82.LFL` to `85.LFL` hold sounds 33 to 64, single
  blocks for the MT-32, which ScummVM reads only when the sound card is set to Roland.

### Phase 2: room graphics (done)

In `Distaff.Scumm.Graphics`:

- `gfx.cpp`: the EGA picture format (`EgaBitmap`: `Gdi::drawBitmap`, `drawStrip` and
  `decodeMask` for `GF_16COLOR` and `GF_OLD_BUNDLE`, `drawStripEGA`, `decompressMaskImg`), with
  its one mask. Strips are drawn left to right into the room's own picture, since a copying run
  takes the pixels to its left.
- `object.cpp`: drawing a room with its objects (`RoomRenderer`: `drawRoomObjects`,
  `drawRoomObject`, `drawObject`), by state and parent, each object's mask replacing the room's
  where it is drawn. Objects without an image of their own point at another object's, or at the
  first code block; an image belongs to its object when it has as many strips as the object is
  wide.
- `palette.cpp`: the 16 EGA colours (`Palettes.Ega`).
- Player: `--room N [--objects none|initial|all] [--mask] [--zoom N] [--output file.png]` writes a
  room as a PNG and lists it.
- Checked against the EGA release: all 76 rooms and the 618 images that belong to their objects
  decode within their data; the title room's picture and mask are pinned. Rooms 1 (the title), 2
  (the opening), 9 (the Loom), 28 (the dragon's cave) and 34 were looked at, not yet compared
  with ScummVM screenshots.
- Moved to phase 4, because the scripts set them (`o5_roomOps`): the room colours
  (`SO_ROOM_COLOR`, the `_roomPalette` that `drawStripEGA` draws through), the shadow palette
  (`SO_ROOM_PALETTE`) and colour cycling.

### Phase 3: scripts (done)

In `Distaff.Scumm.Scripts`:

- `script_v5.cpp`, `script_v4.cpp`, `script_v3.cpp`: the opcode table (`OpcodeTable`, generated by
  `tools/port_opcodes.py` from `ScummEngine_v5::setupOpcodes` with v4's and v3's changes applied;
  106 handlers), and the decoder (`ScriptDecoder`), with each handler's operands as its fetches
  read them in a version 3 small-header game: variables as words with their 0x2000 index word
  (`readVar`, `getResultPos`), `roomOps` fetching its first two operands before the
  sub-operation, `actorOps` through `convertTable`, `print`'s version 3 height, `expression`
  running a nested instruction. Sub-operations are decoded into named lists (`SubOperation`).
- `beginOverride` takes the jump after it as its own (`ScummEngine::beginOverride`): execution goes
  on after the jump, and the jump leads to where a skipped cutscene resumes.
- Player: `--script N` and `--room-scripts N` disassemble along every path execution can take.
- Checked against the EGA release: every global script, every room's entry, exit and local
  scripts, and every object's verb scripts decode along every reachable path (987 scripts,
  25,127 instructions); and decoded straight through, every one of them (114 global, 873 in
  rooms) ends exactly where its code does.

### Phase 4: the game loop (done)

- `script.cpp`, `script_v5.cpp`, `script_v4.cpp`: the script engine (`ScriptEngine`): 80 slots with
  their 25 local variables and arguments, nesting, the 800 variables with version 3's bit
  variables inside them (`readVar`, `writeVar`), freezing by count, the cutscene stack and
  overrides, the sentence queue and script, and the handlers that touch only script state.
- `scumm.cpp`, `room.cpp`, `vars.cpp`, `camera.cpp`: the world (`GameWorld`): the step
  (`scummLoop`, timers, delays at the DOS timer's 1193182/5041 Hz), room changes (`startScene`,
  entry and exit scripts, pseudo-rooms), Loom's start-up variable values, the screen layout
  (`initScreens`), the camera (`Camera`), objects' states, owners, classes, the inventory and
  names, verbs as the scripts set them up, the string resources, the cursor and user-put counts.
- `string.cpp`, `actor.cpp`: messages without the drawing (`printString`, `actorTalk`,
  `stopTalk`, `displayDialog`, `handleNextCharsetCode`, `convertMessageToString`): how long each
  stays up, which the scripts wait on.
- `o5_roomOps` and `palette.cpp`: the room colours (drawn through by `EgaBitmap`) and the shadow
  palette. No version 3 room has colour cycling of its own.
- The copy protection: as ScummVM does by default, room 69 starts script 205 in place of 201
  (`o5_startScript`); `--copy-protection` keeps the Book of Patterns check.
- Brought forward from phase 7, to get past the proficiency screen: the mouse variables and
  `checkExecVerbs` for clicks in the view and keys (`GameWorld.Input`).
- Player: `--run [steps] [--click step:x,y]... [--copy-protection] [--screenshot file.png]` runs
  the game headless and reports the rooms, messages and sounds.
- Checked against the EGA release: from boot, the proficiency screen (room 69); with PRACTICE
  clicked, the Lucasfilm Games title (room 1), the opening (rooms 2, 1, 2, 53) and Bobbin on the
  cliff in room 2 ("Rise, son of Cygna." ... "Better get down to the village."); with the copy
  protection kept, the Book of Patterns question.
- Not yet: text, verbs, boxes drawn by `drawBox` and the cursor are not drawn (text and boxes
  came in phase 6); sounds are recorded but not played, and none is ever running; room fades
  and shaking.

### Phase 5: actors and costumes (done)

- `costume.cpp`, `base-costume.cpp`: the classic costume format (`Costume`), the limbs'
  animation (`CostumeState`: `costumeDecodeData` with its limb mask, `increaseAnim` with
  version 3's sound counting) and drawing (`CostumeRenderer`: `setPalette`, `setFacing`,
  `drawLimb`, `byleRLEDecode`), by way of Maniacal's port, drawn straight into the room's
  picture so the room's mask can hide an actor where its box says (`_zbuf`).
- `actor.cpp`: `Actor` and `Actor_v3`: costumes, showing and hiding, frames by role, facing and
  turning, `adjustXYToBeInBox`, `adjustActorPos`, `startWalkActor`, `walkActor`,
  `calcMovementFactor`, `actorWalkStep`, `findPathTowardsOld`, `animateCostume`; the world walks,
  sorts by depth and draws them (`walkActors`, `processActors`), turns them to objects
  (`faceToObject`) and walks them to each other (`walkActorToActor`). Version 3 has no scaling.
- `boxes.cpp`: the box matrix of version 3 (`getNextBox`), the gates between boxes and the
  closest points (`BoxGeometry`), box flags the scripts change (`o3_setBoxFlags`).
- `palette.cpp`: the shadow palette remaps the colours shown (`updatePalette`).
- Player: `--trace-actor N` with `--run` prints an actor's place, box and walk state each step.
- Checked against the EGA release: all 159 costumes draw every frame facing each way (four more
  index entries are leftovers pointing into other resources); after the opening Bobbin stands on
  the cliff, and a click on the path below walks him through boxes 0 to 6 to the point nearest
  it. His drop from the rock's edge to the path, between boxes 3 and 5, is quick, as the
  nymph's drop in local script 201 is scripted; not yet compared with ScummVM.

### Phase 6: text (done)

- `charset.cpp`: the v3 font in `99.LFL` (`Charset`: `setCurID`'s count, height and width
  table, `getCharWidth`, `getStringWidth`, `drawBits1` with its normal and outline shadows),
  and `CharsetRendererV3`'s `setColor` (bit 6 an outline, bit 7 a shadow) and `printChar`.
- `gfx.cpp`: the screen's bands (`VirtScreens`: `initScreens`, `findVirtScreen`, the text
  surface and the composition of `drawStripToScreen`), `restoreCharsetBg` and `drawBox`. The
  room is drawn afresh each frame, so the main band keeps only what is drawn over it, and that
  goes where ScummVM would draw the room again: everything on a new room or a camera jump, the
  columns scrolled out of view, the strips of an object whose state changes
  (`markObjectRectAsDirty`), an object drawn, and where an actor is drawn (`resetActorBgs`).
- `string.cpp`: `displayDialog` (the pen, centring each line, the text going unless kept),
  `newLine`, `drawString` for `print` in slot 1, and `actorTalk`'s colour. Version 3 keeps a
  text's place, line height and colour as the slot's defaults after it prints
  (`decodeParseStringTextString`); without that Bobbin's lines go to the top left.
- Checked against the EGA release: the proficiency screen's levels and narration (the ™ is the
  font's `]^`), PRACTICE lighting up when clicked and the screen blacked out by `drawBox`, the
  nymph's lines over the room and Bobbin's below it, each gone when its time is up. Shadows and
  outlines are checked on a one-pixel glyph; the opening has none.
- Not yet: the overhead position of speech, which Loom's scripts never ask for; text is not
  compared with ScummVM screenshots.

### Phase 7: the distaff and input (done)

- `verbs.cpp` (`GameWorld.Verbs`): `o5_verbOps`, `o5_saveRestoreVerbs`, `killVerb`,
  `setVerbObject` (an object's image copied out of the room on screen and kept),
  `drawVerb`, `drawVerbBitmap`, `restoreVerbBG`, `restoreBackground` and `findVerbAtPos`.
  Loom's verbs are all images: the distaff's parts, the staff and the icon of what is pointed
  at. Text verbs draw in slot 4 as ScummVM draws them, without the highlight under the mouse.
- `input.cpp`: clicks on verbs go to the verb script as the verb's (`checkExecVerbs`); the keys
  of `processKeyboard` that version 3 keeps with the original interface: Escape skips a
  cutscene and hands the game its cutscene key, the period ends a line, F1 to F9 are 315 on,
  Ctrl and a letter its control code, the pause key pauses (without its banner).
- `cursor.cpp` (`GameWorld.Cursor`): Loom's cursor made from the font's character 1
  (`redefineBuiltinCursorFromChar`), its hotspot, the colour cycling of `animateCursor`; the
  engine draws it over the frame it presents.
- `gfx.cpp`: the dark room and the flashlight (`drawFlashlight`, `Flashlight`): 7 by 7 strips
  around the ego, Loom v3's 4 right and 12 up, the corners masked as versions 1 to 3 mask them.
- `object.cpp`: `o5_getDist` (`getObjActToObjActDist`), which the village's exit scripts use.
- The player: `distaff <folder>` plays in an SDL window (the host from Maniacal), with
  `--scale N` and `--fullscreen`; `--key step:K` presses keys in a headless run, which also
  lists the verbs that are on.
- Checked against the EGA release: a scripted run walks from the cliff through the village and
  the tents to the Sanctuary, sees the council, picks up the distaff (drawn below the room with
  its staff and the notes c, d and e), and weaves Opening (e c e d) on the egg, after which
  Hetchel speaks; Escape skips the opening; the cursor's shape and colours; the flashlight in a
  room with its lights put out (Loom only uses it in room 30, not yet reached). The window runs.
- Not yet: Dyeing and the other drafts are not played; the pause banner; the restart question.

### Phase 8: saves (done, not yet checked against ScummVM)

- `saveload.cpp` (`Saves`, by way of Maniacal): the save file (header, information section,
  gzip) and the state field for field in ScummVM's order (`saveLoadWithSerializer` with
  `ScummEngine_v5`'s cursors, `Actor_v3`'s walk at version 3's revision, 13 actors), written in
  save version 108 (ScummVM 2.7's), read from 108 to 124; the sound engine's block is kept as
  it is (the PC speaker's player writes none).
- `GameWorld.Saving`: the world as the state (`Capture`) and back (`Restore`, as `loadState`:
  the room without its scripts, its boxes with the flags the scripts left, objects moved, the
  bands cleared). Strings, verbs (an image verb keeps its copy of the image, as `rtVerb` does),
  actors' and objects' names and carried objects' code are resources; a running script is
  saved where it last yielded or nested (`ResumeOffset`). Strings now keep their zero, and
  `stringOps` reads a character (`GET_STRING_CHAR`) and copies up to the zero.
- `script_v4.cpp`: `o4_saveLoadGame` (slots, the drive, whether a slot has a save, saving under
  the name in strings 9 to 20, loading, with the name changed first as the original allowed)
  and `o4_saveLoadVars` (the names read back from the saves). A load in the save room carries
  on the loaded state's current script from where the loading one stands; a save from outside
  it starts the game over and loads again (`_loadFromLauncher`).
- `scumm.cpp`: after a load from outside the save screen, `ScummEngine_v3::scummLoop_handleSaveLoad`
  for Loom: a save made in the save room ends the save script (`terminateSaveMenuScript`); one
  made elsewhere goes through the save room inside a cutscene. ScummVM clears bit 13 of
  variable 214 there on DOS; this release's own save script clears bit 14 (`Bit[3438]`), and
  without that the distaff stays off after the load, so Distaff clears bit 14, as ScummVM does
  for the FM Towns.
- `o5_getStringWidth`, which the save screen uses to stop a name at the slot's edge.
- Drawing: objects `drawObject` draws stay over the room's own objects until their strips are
  drawn again (the draw queue), so the save screen's OK and CANCEL show over its buttons.
- The player: `--load file` starts from a save as ScummVM's launcher does (window or headless);
  `--save step:file` saves in a headless run as ScummVM's menu does; the game's save screen (F5)
  keeps its saves in `--saves folder` (`%APPDATA%\Distaff\saves` by default) as `<target>.sNN`,
  the target `loom` unless `--target` says otherwise.
- Checked against the EGA release: a save read back saves the same state again (the mouse
  aside, which ScummVM's original interface does not restore); a save on the cliff, loaded,
  plays on as the game did; the save screen saves under a typed name and, in another game,
  loads it back to the Loom with the distaff; that save and one made between steps both load
  from the launcher to the Loom with the distaff.
- Not yet: no save has been loaded in ScummVM, nor a ScummVM save here; no sounds are listed
  in a save, so ScummVM reloads them as they start; the locked resources are not saved.

### Phase 9: sound (done)

- `sound.cpp` (`SoundSystem`, by way of Maniacal): the queue a step's sounds wait in
  (`startSound`, `processSoundQueues`), `stopSound`, `stopAllSounds`, `isSoundRunning`, the
  music timer the scripts read (`updateMusicTimer`), and `playActorSounds`. The opcodes
  (`o5_startSound`, which restarts the music timer, `o5_startMusic`, `o5_stopSound`,
  `o5_stopMusic`, `o5_isSoundRunning`) now use it, and the sound card variable names the
  device (0 speaker, 1 PCjr, 3 AdLib, `setSoundCardVarToCurrentConfig`). A load stops the sounds.
- `players/player_v2base.cpp`, `player_v2.cpp` (`PlayerV2`, Maniacal's port): the PC speaker
  and PCjr play each sound's first block, with version 3's own music timer (`_isV3Game`: the
  tempo field starts it, every 125 ticks). Its tables come from
  `tools/port_sound_tables.py`, which regenerates them unchanged from this checkout.
- `players/player_ad.cpp` (`PlayerAd`): the AdLib plays each sound's second block after its
  header: music (Loom's timer limit and tempo meta event, rhythm instruments) and up to three
  effects with their envelopes, the timer called 472 times a second between samples as
  `EmulatedChip::readBuffer` calls it. The volumes it scales operators by are the full 255;
  the host's master volume applies instead. Seeking the music back after a load is not ported.
- `audio/softsynth/opl/mame.cpp` (`Opl.MameOpl`): MAME's OPL2, which ScummVM picks for an OPL2
  by default. It matches ScummVM's own build sample for sample: `tools/opl-reference` compiles
  ScummVM's `mame.cpp` with MSVC against small stand-in headers, and `OplTests` checks a
  register script covering voices, envelopes, waveforms, vibrato and tremolo, and the rhythm
  section (3.4 seconds) against its output. The drums' noise seed is a parameter (ScummVM
  seeds it from the clock).
- The player: `--sound speaker|pcjr|adlib` (AdLib by default, as ScummVM's automatic choice
  picks for this release), and `--wav file.wav` writes a headless run's sound.
- Checked against the EGA release: the proficiency screen is silent; the title's music
  (sound 25) starts with PRACTICE and plays through the opening on each device, its first
  seconds pinned for each; the AdLib's music is tonal, its strongest notes chords (B flat, D, F
  at 12 seconds). Not compared with recordings or with ScummVM's output.
- Out of scope: MT-32 and the Roland Upgrade's sounds; CMS.

### Phase 10: the whole game (done)

- `WalkthroughTests` play the EGA release at the practice level from the proficiency screen to
  "The End" in ten sections: the Elders, the island, leaving the island, Crystalgard and the
  shepherds, the dragon, the caves, the forge, the Bishop, the void, and the Loom. Each section
  loads the save the one before it made into a new world and saves at its end, so every save on
  the way is played on from. Each pins what was said, the room it ends in, the drafts learned and
  used (the flags in the game's draft table) and, where they grow, the notes the distaff plays. The
  whole game runs in about three seconds.
- `Walkthrough` plays as a player does: it waits for control (no cutscene, message or sentence
  script, Bobbin standing, the camera still), clicks and double-clicks objects by number,
  scrolling to them first, and leaves by exits, clicking again when a walk box's cutscene cuts
  the walk short. It can point at an object while the game is still talking, and it spins a draft
  by reading the draft's notes from the game's table, which is shuffled each game.
- No engine change was needed: everything the scripts asked for worked. Some things the run
  showed about the game itself:
  - The distaff gains f once Opening, Dyeing and Straw into Gold have all been used. Dyeing must
    go on the white wool, and Straw into Gold on the straw in the wheel's tent.
  - g comes at the waterspout, a at the dragon, and b and the high C at the Loom.
- Not covered: the Standard and Expert levels, optional scenes (the graves and the chalice in
  Crystalgard), deaths and other ways through. Nothing has been compared with ScummVM.

## VGA CD

The VGA CD release is SCUMM version 4 (`ScummEngine_v4`): the same game, with 256 colours, a
new interface, scaled actors, and the music and voices on one CD audio track. Its phases build on
the EGA engine, as the EGA's built on each other.

### Phase 11: resources (done)

- `resource_v4.cpp` (`ResourceIndex.ParseV4`): `000.LFL`, not encoded, is blocks of a 32-bit size
  and a 2-letter tag. `RN` holds the 78 room names (XOR 0xFF), `0R`, `0S`, `0N` and `0C` the
  directories (a room and a 32-bit offset each; a room's room is its disk), and `0O` the 1000
  global objects. Every entry has an offset; those for rooms the disk does not hold, and their
  resources, say room 0.
- `DiskBundle`: `DISK01.LEC`, XOR 0x69 (`getEncByte`), is an `LE` block whose `FO` block gives
  each room's offset (`readRoomsOffsets`); there each room's `LF` block holds its number, then
  the room and the scripts, costumes and sounds stored with it. A resource is 8 bytes past its
  room's offset and its own (`loadResource`), with a 6-byte header (`_resourceHeaderSize`).
- `ResourceLoader` reads both layouts. The charsets are `901.LFL` to `904.LFL`, not encoded:
  the size their first 32 bits give, and 11 bytes more (`ScummEngine_v4::loadCharset`).
- `Room.ParseV4`: a room is a chain of blocks (`findResourceData` with `newTag2Old`): `HD` (width,
  height, object count), `BM` (the picture), `PA` (the palette), `SP`, `CC` (colour cycling),
  `SA` (scale slots), `BX` (20-byte boxes with a scale, then the matrix), `EX`, `EN`, `LS`
  (local scripts, their number first), `OC` and `OI` for each object, `NL` and `SL` (the sounds
  and scripts loaded with the room), `LC`. Object code blocks have the EGA's fields 2 bytes
  further on (`ScummEngine_v4::resetRoomObject`). The VGA CD numbers its objects differently: the
  cliff's leaf is 79, not 154.
- `ScriptDecoder` takes a version. Version 4's opcode table (`tools/port_opcodes.py` now emits
  both) has `matrixOps` where version 3 has `setBoxFlags`, and no `waitForActor` or
  `waitForSentence`. Its `roomOps` fetches the operands after the sub-operation, and its
  `print` left-aligns where version 3 reads a height. `--script N` and `--room-scripts N`
  disassemble the VGA CD; `--room N` lists a room without drawing it.
- Checked against the VGA CD release: the disk holds 78 rooms, 122 scripts, 166 costumes (the
  index reaches 165 of them), and 32 sounds (30 `SO` blocks and 2 bare 24-byte blocks); every
  room parses; all 122 global scripts (10512 instructions) and all 910 room, local and object
  scripts (18698 instructions) decode straight to their ends.
- Not yet: the sounds' contents (with the CD audio), costumes' contents (with the actors).

### Phase 12: room graphics (done)

- `gfx.cpp` (`VgaBitmap`): a picture is a 32-bit offset of its first z-plane and a 32-bit
  offset per strip (`drawStrip` for `GF_SMALL_HEADER`); each strip's first byte names its codec,
  whose last digit is the colour width (`decompressBitmap`). Ported: raw (1), the zigzag codecs
  down the columns (14 to 18) and along the rows (24 to 28) (`drawStripBasicV`, `H`), the
  major-minor codecs (64 to 68, 104 to 108; `drawStripComplex`, `MajMinCodec`), and the
  transparent form of each, which leaves colour 255 undrawn (version 4 rooms have no `TRNS`).
  The FM Towns', 3DO's and HE's codecs are not.
- Z-planes (`getZPlanes`, `decodeMask`, `decompressMaskImg`): the first follows the strips, each
  next one is a word further on, and a plane has a word per strip giving where its mask starts,
  or 0 for nothing masked. A room's picture sets how many there are (`_numZBuffer`, at most 4
  buffers counting the picture), and its objects use the same count. The mask keeps the planes
  as bits (bit 0 for plane 1), which leaves the EGA's single plane as it was.
- Object images (`getObjectImage`): 8 bytes into an object's `OI` block; one image per object,
  whatever its state. Objects without one have an 8-byte block.
- The room palette (`setPaletteFromPtr` for `GF_SMALL_HEADER`): a byte count, then 8-bit red,
  green and blue. `RoomRenderer.PaletteOf` gives it; `--room N` draws the VGA CD's rooms in it.
- Checked against the VGA CD release: the strips use only codecs 1, 14 to 18 and 24 to 28; every
  room picture and all 694 object images decode, drawn over their rooms; 26 rooms have no
  z-plane, 50 one and 2 two. The cliff, its z-plane (the rocks and trees in front of the path)
  and its palette are pinned, and drawn with all its objects it shows the title's logo, the leaf
  and the split tree in place. The complex codec and the transparent forms, which Loom's own
  pictures do not use, are checked on strips built by hand. Not compared with ScummVM's output.

### Phase 13: costumes and actors (done)

- `costume.cpp` (`Costume.ParseV4`): a VGA CD costume has the EGA's layout 2 bytes further on,
  a palette of 16 colours (format `0x58`) or 32 (`0x59`) of room colour numbers where the EGA has
  its colour byte, and in its animations a word for each limb's first command, `0xFFFF` hiding

### Phase 21: sound

Part 1, the CD (done):

- `FlacTrack` in `Distaff.Audio`: a FLAC decoder of its own (RFC 9639), no package: the stream
  information, frames and their headers, constant, verbatim, fixed and linear-prediction
  subframes, Rice-coded residuals with escapes, wasted bits, and the three stereo
  decorrelations. The file is read whole and decoded a frame at a time; a seek finds its frame
  by the frame headers alone, each checked by its CRC-8. Samples are scaled so that the CD
  player's rounding gives back the 16-bit samples, as ScummVM's FLAC stream has them. Track
  files are looked for as `.flac` and `.fla` before `.ogg`, as ScummVM does (`STREAM_FILEFORMATS`).
- `PlayerTowns` (`Player_Towns_v1` for version 3): a sound's type, its 14th byte, says what it is.
  Type 2 plays part of a CD track: its volume, unless the scripts gave the sound one
  (`resourceRoutines` 36, and its note with 37), then the track, how many times (255 for ever)
  and its start and end in minutes, seconds and frames (`playCdaTrack`); a sound already playing
  on the CD goes on. Stopping it, or all sounds, stops the CD and its timer (`stopCDSound`).
  The CD query answers the sound playing on the CD (254) and its volume (255).
- The CD's volume (`setVolumeCD`) is heard as ScummVM's Towns audio sets its CD channel: half
  of each side's, of which 6 bits count, the louder to the power of 1.5 over 255, the balance

## iMuse

The second step of the Roland Upgrade: the music engine ScummVM plays its sounds with, on the
MT-32 (`Distaff.Scumm/Sound/IMuse`, and `PlayerImuse`, which carries it).

- `MidiParserRo` reads the Upgrade's own format (ScummVM's `MidiParser_RO`): "RO", then channel
  messages, delays (F0, and F1 for 256 more), markers (A0 to AF, the music timer counting them),
  a loop marker and the end; `MidiParser` is ScummVM's generic parser under it, the timing of
  events against the timer rate, notes left hanging by a jump, the end looping round or stopping.
- `IMuseEngine` is `IMuseInternal` for a native MT-32 and the old system: 8 players, 32 parts,
  parts given channels by priority (dynamic allocation, as Loom has it), volumes, the music
  timer (the most any player has counted); `Player` and `Part` are iMuse's, for RO sounds.
  `IMuseDriverMt32` is `IMuseDriver_MT32` for the old system: nine channels on the module's
  parts 1 to 8 and its rhythm part, programs set through each part's patch temp area, repeated
  controllers and bends left out, and the module's setup when it opens (its display greeted,
  reset, master tune, reverb, channels, partial reserve, volume, rhythm keys, bend ranges).
- `PlayerImuse` sets it up as ScummVM's `setupMusic` does for an MT-32, at the music volume
  (192 unless set); the MT-32's timer, 250 times a second of its own 32 kHz output, moves iMuse
  on, as `MidiDriver_MT32` (a `MidiDriver_Emulated`) calls it. `ResourceLoader.LoadRolandSound`
  reads a sound as the Upgrade's single block, and `PlayerImuse.RoResource` makes it what iMuse
  takes ("RO" and the block after its header).
- Found on the way: Munt's output depends on how its rendering is split (rendered straight
  through, or 32 or 128 or 1000 frames at a time, its own C++ gives four different results).
  ScummVM's driver renders it 128 frames at a time: its mixer's rate converter reads 256 frames
  at a time, which `MidiDriver_Emulated` splits at its timer's ticks. `Mt32Emulator` (Daventry's,
  which rendered 32 at a time) now renders 128 at a time, and converts its rate as ScummVM's
  mixer does (`RateConverter_Impl`: copied at the same rate, otherwise interpolated with a
  14-bit fraction, rounded, from a frame in), where it had interpolated with 16 bits, truncated.
- `tools/imuse-reference` builds ScummVM's own iMuse, its RO and MIDI parsers and its MT-32
  driver to play a sound to a device that writes what reaches it, timed as ScummVM's driver
  times it, and `rate-reference` from ScummVM's rate converter; `tools/mt32-reference` renders
  what the first writes through Munt, 128 frames at a time. `ImuseTests` plays every sound read
  as the Upgrade reads it for three minutes and every message, data set and music timer is
  ScummVM's (sounds 1 to 32, not Roland data, stop at their first byte as there); the overture's
  first minute at 44100 Hz is ScummVM's sample for sample, on the MT-32 1.07 and the CM-32L 1.02.
- Left out, as Loom never reaches them: the scripts' commands to iMuse (only `soundKludge`
  reaches them, which Loom's scripts do not use), and with them the command queue, triggers,
  hooks, jumps, loops, scans and faders' targets; iMuse's own sysex messages and Roland
  instruments (an RO sound has none); the AdLib and other drivers. Saving iMuse's state came
  with step 4 (see "iMuse in saves").

## The CMS

The EGA's fourth sound card, the Creative Music System (Game Blaster), as ScummVM plays it
(`--sound cms`; the scripts' sound card variable is 2, `setSoundCardVarToCurrentConfig`):

- Which block of a sound it plays (`readSoundResourceSmallHeader` for `MDT_CMS`): the AdLib
  block, from its size word, when its seventh byte is 0x80, a music track; the speaker and PCjr
  block otherwise. In Loom sounds 13 to 32 are tracks (24 is not on the disks), 1 to 12 effects.
- `CmsSynth` ports DOSBox's SAA1099 emulator (`audio/softsynth/cms.cpp`): two chips of six
  square-wave channels, with a volume for each side, two noise generators and two envelope
  generators, mixed into stereo, written through ports 0x220 to 0x223.
- `PlayerV2Cms` ports `Player_V2CMS`, ticked 236 times a second between runs of samples as
  ScummVM's emulated chips are (`EmulatedChip::readBuffer`). A track plays on 8 voices, 4 on
  each chip, each note taking a free voice and its channel's instrument: an attack, decay,
  sustain and release, a vibrato and a tremolo, from the track's header; the voices move on every
  other tick, the notes at the track's tempo; a track goes round unless it says to end. An
  effect runs the PCjr's programs through `PlayerV2`'s sequencer, its three voices and noise set
  on the first chip; while a track plays, effects wait. ScummVM plays the chips at full volume,
  whatever the music and effects volumes (`setMusicVolume` does nothing), and keeps nothing of
  them in a save, as for the PCjr.
- `tools/cms-reference` builds ScummVM's `Player_V2CMS` and its emulator to play a sound. Every
  sound the CMS plays, 1 to 32, renders sample for sample as there for 10 seconds; `SoundTests`
  pins 25 seconds of the title's music and 10 of an effect (sound 5) to its hashes, the title's
  music in the game, the sound card variable, and the full volume. Sounds 33 to 64 are the Roland
  Upgrade's, which the scripts start only for the MT-32; read as two blocks they are not sounds,
  and ScummVM's PCjr player, like its CMS one, runs off them.
- Not listened to against ScummVM's window.

## The FM Towns' picture layer

The rest of the FM Towns' smooth scrolling (`gfx_towns.cpp`):

- The picture layer is 512 columns going round (`VirtScreens.TownsPicture`). The camera's view,
  the room under what is drawn over it, is copied in at the end of each frame and when a room's
  effect is drawn, from a column that moves 8 when the camera moves a strip
  (`towns_drawStripToScreen`, `_scrollDestOffset`); the screen shows the layer from a column of
  its own that follows a pixel a tick (`hScroll`). So the columns shown behind the camera keep
  what was copied there while the camera had them in view: in the opening's climb, 150 frames
  show an actor there in the place and pose it had, where the room drawn now would have it moved
  on or animated. Loom never clears the layer (`_townsClearLayerFlag`). ScummVM copies only the
  strips drawn again; Distaff copies the whole view, which holds the same where nothing was
  drawn again. Without smooth scrolling the layer shows just the camera's view, as before.
- Semi-smooth scrolling (`semi_smooth_scroll`, off by default as in ScummVM; the player's
  `--semi-smooth-scroll`): while the game runs without waits between frames
  (`VAR_TIMER_NEXT` 0), as the opening's fast camera does, the layer scrolls 4 pixels a tick.
  The climb then falls at most 132 pixels behind instead of 192, and the messenger's first words
  come at 30.52 seconds instead of 32.91.
- Not ported, and not a difference: ScummVM's catch-up (`_refreshNeedCatchUp`), which takes
  several ticks of scroll in one screen update once its updates average longer than a 60th of a
  second. Distaff's game time does not wait on the screen: every tick scrolls as its own step,
  as ScummVM's does on a machine that keeps up.
- The room's own picture is now decoded once for its colours and drawn over in a copy, since
  the view is copied every frame; the tests take about 15% longer than before, not twice as

- `TownsScreenTests` pins the layer going round and keeping the columns the view has left;

## The CD timer while the menu is up

A menu or banner pauses the engine (`pauseEngine`), and that pauses the sounds
(`pauseEngineIntern`, `pauseSounds`) when they are not paused already, and starts them again
when it goes. On the VGA CD and the FM Towns (`GF_AUDIOTRACKS`), pausing the sounds stops the CD
timer only if the music timer is above 0, and starting them again starts it only then
(`pauseCDSounds`). Distaff had stopped the timer while the menu was up, whatever the music
timer, and it went on as before after.

- `PauseSounds` is now the one way the menu, its banners and the old-style banners pause and
  start the sounds, acting only when that changes, as ScummVM's nested pauses do. On the CD
  releases it stops and starts the CD timer as `pauseCDSounds` does, and the timer counts on in
  the menu's steps when it was not stopped, as it does on its own thread in ScummVM.
- So the menu opened while a line is being spoken holds the music timer where it was, and the
  line's text and pictures wait with it; opened in the frame a line starts, before the music
  timer has counted (it is 0 until the next frame's `updateMusicTimer`), it leaves the timer
  running, and the line's timing has moved on by the time the menu was up when it goes. As in
  ScummVM, the menu's key is taken before the frame sets the music timer (`processInput`
  before `updateMusicTimer`).
- `VgaMenuTests` pins both on the cliff, with Bobbin's line on the leaf: held once it has counted,
  and counted through 200 steps of the menu, at 60 counts a second, when opened as it starts.
- A load from the menu goes through `loadState`'s own pause (see "Frames after a load"): the
  timer then runs on from the load if the loaded music timer is above 0.
- Worked out from ScummVM's code; not compared with ScummVM's window, which would need the menu
  opened there by a key at the right frame.

## Recording a video

A run, or a walkthrough, recorded as a video, as a window shows and plays it.

- `GameWorld.Stepped` tells a recorder of each step. `VideoRecorder` then shows the frame for the
  step's length (`StepLength`, as `ScummEngine.Tick` waits) and reads the sound over the same
  time, as the audio device pulls it. The video runs at 60 frames a second, each frame the game's
  frame showing at its time; the sound and the frames are counted from one clock, so they cannot
  drift apart.
- The recording's clock is the host's, not the game's: the game's time stands while a banner or
  the VGA CD's menu is up, and the window still shows them.
- A walkthrough's sections are worlds of their own, each loaded from the save the one before made:
  the recorder moves from one to the next, the video going on where it was.
- `FfmpegEncoder` pipes the frames raw to ffmpeg, scaled up by whole pixels and encoded as H.264
  (`-tune animation`, CRF 18), and writes the sound to a WAV file beside the output; at the end
  the two are put together, the sound as AAC, and the files beside it removed. The scale is 4 by
  default, even so that the colour's half-size planes fall on the game's pixels.
- `--video file.mp4` (and `--ffmpeg path`) on a headless run; `DISTAFF_RECORD_VIDEO` (and
  `DISTAFF_FFMPEG`) for the walkthrough tests' `Records_the_whole_game`, at Practice: the EGA on
  the AdLib, the others with their CD audio. All three play to the end so: the EGA in 1:16:35,
  the FM Towns in 1:16:44, the VGA CD in 1:13:00.
- Checked with a stand-in encoder: the frames and samples written are the time recorded at their
  rates, from world to world and through the pause banner. ffmpeg itself is checked when it is to
  be had (`Ffmpeg_writes_the_video`); a run with none says it needs it.

## The libraries' public API

0.1.0-alpha published the libraries with nearly all of the engine public (141 types in
`Distaff.Scumm`, 13 in `Distaff.Audio`): the port never chose an API, and `GameWorld` handed out
its script engine, actors, verbs, screens and sound. A 1.0 would have frozen all of it. 0.2.0
chooses one, as Maniacal's is chosen:

- `Loom` is the front door: `Loom.Open(folder)` names the release (`Description`, `Variant`,
  `Version`, `IndexMd5`, `Target`), and gives a headless game (`Play`), an inspector (`Inspect`),
  or the engine for a host (`CreateEngine`).
- `GameWorld` keeps what a headless driver needs: boot, step, click, keys, the frame, saves,
  the settings, the messages, and its sound as `Audio`, `MusicVolume` and `SfxVolume`. In place
  of the engine's own objects it gives snapshots: `GetActor` and `ActorsHere` (`ActorInfo`),
  `RunningScripts` (`RunningScript`), `ShownVerbs` (`VerbInfo`), `CameraX` and `Variables`.
  What the script engine and the actors ask of it (`IScriptHost`, `IActorWorld`) is implemented
  explicitly, so it stays internal.
- `Inspection.GameInspector` draws a room (`RoomPicture`: the picture, its mask and objects) and
  disassembles scripts (`ScriptListing`), and lists the rooms and scripts. The player's `--room`,
  `--script` and `--room-scripts` are built on it, and the whole player on the public API alone:
  it does not see the libraries' internals, which is the check that the API is enough.
- Public too: the host contract (`Engine`, `IHost` and its drivers, the headless host, input,
  logs, `TickResult`, `AudioVolume`), `Rgb`, `RgbFrame` and `PngWriter`, the game's files and
  saves, the sound devices and `IMidiDevice`/`ICdTrack`, `WavWriter`, and the video recorder.
  Internal: rooms, costumes, scripts, the sound players and iMuse, screens, resources and
  detection. 55 public types are left in `Distaff.Scumm`; in `Distaff.Audio`, 8: `CdTrackFiles`,
  `Mt32Emulator` and the ROMs' types, the FLAC and Vorbis decoders and Munt's settings internal.
- Every public member is documented (CS1591 is an error in both libraries); the host contract's
  comments came from Maniacal's, where its code is the same. `PublicAPI.*.txt`
  (`Microsoft.CodeAnalysis.PublicApiAnalyzers`) keeps the surface, 795 symbols and 66: a change
  fails the build until it is written there.
- Package validation against 0.1.0-alpha was off for 0.2.0, whose narrowing is on purpose. Since
  0.2.0-alpha was published, both libraries are validated against it, and its API is in
  `PublicAPI.Shipped.txt`: a public member removed or changed fails the build (RS0017) and the
  pack, and a new one goes into `PublicAPI.Unshipped.txt` until the next release.
- Tests that took internal enums as theory parameters take their names instead, as xUnit's
  public test methods cannot have internal parameter types. `PublicApiTests` uses the API as a
  package user would, and a console app outside the repository, restoring the packed packages,
  ran the README's example.
