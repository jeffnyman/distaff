# Distaff roadmap

What is done, what comes next, and where each piece comes from. Source references are to the
ScummVM checkout at `../_loom/scummvm/engines/scumm`.

## Design

ScummVM builds Loom's engines as a chain of subclasses: the EGA release runs on
`ScummEngine_v3old : v3 : v4 : v5 : ScummEngine`, the FM Towns release on `ScummEngine_v3` (the
same chain, without `v3old`), and the VGA CD release on `ScummEngine_v4`. Much of what Loom runs
on lives in the V5 and base classes, mixed with code for later games (iMUSE, HE, SMUSH, AKOS).
Distaff does not port that chain. It has one flat engine with the release as data, and it takes
from each ScummVM function only the branches that `GID_LOOM` and versions 3 and 4 reach. ScummVM
has about 200 `GID_LOOM` special cases; each is ported or ruled out on purpose, not by accident.

The three releases split the work like this:

| | EGA (v3old) | VGA CD (v4) | FM Towns (v3, `GF_OLD256`) |
|---|---|---|---|
| Engine class | `ScummEngine_v3old` | `ScummEngine_v4` | `ScummEngine_v3` |
| Files | `NN.LFL`, XOR 0xFF | `000.LFL`, `90x.LFL`, `DISK01.LEC` XOR 0x69 | `NN.LFL`, not encoded |
| Resource headers | 4 bytes (`GF_OLD_BUNDLE`) | 6 bytes (`GF_SMALL_HEADER`) | 6 bytes |
| Index | `ScummEngine_v3old::readIndexFile` | `ScummEngine_v4::readIndexFile` | `ScummEngine_v3::readIndexFile` |
| Colours | 16 (`GF_16COLOR`, `drawStripEGA`) | 256 | 256, with the Towns' text layer (`gfx_towns.cpp`) |
| Scripts | v5 opcodes with v4 and v3 changes | v5 opcodes with v4 changes | as EGA |
| Sound | PC speaker and PCjr (`Player_V2`), AdLib (`Player_AD`), MT-32 (iMUSE) | CD audio (`soundcd.cpp`) | `Player_Towns_v1` and CD audio |

The EGA release comes first: it is the one people think of as Loom, and it has the full
dialogue the CD release cut. VGA follows, because it shares the most with EGA once the 256-colour
drawing and the DISK01.LEC bundle are in. FM Towns comes last.

Every phase ends with a headless check: a screenshot of a known room, or a scripted run of
clicks that reaches a known state.

## Done

- Solution layout, build settings and the host contract (from Daventry by way of Maniacal).
- Detection: ScummVM's 34 Loom MD5 rows (generated by `tools/port_md5_table.py`), the
  variant-to-version table of `detection_tables.h` and `metaengine.cpp`, and identification by
  `00.LFL` or `000.LFL`. The English DOS EGA, DOS VGA CD and FM Towns releases are identified.

## EGA

### Phase 1: resources

- `file.cpp`, `resource.cpp` (`getEncByte`), `resource_v3.cpp`: the XOR-0xFF `.LFL` files, the
  index (`ScummEngine_v3old::readIndexFile`: magic 0x0100, global objects, the room, costume,
  script and sound directories), and loading a resource by its old-bundle header.
- `room.cpp`, `object.cpp`, `boxes.cpp` (reading): the room header, objects, walkboxes and box
  matrix, entry and exit scripts, local scripts.
- Check: every room file is a chain of resources, and the index entries that point at real
  resources are counted and pinned in the tests.

### Phase 2: room graphics

- `gfx.cpp`: the EGA strip codecs (`Gdi::drawStripEGA`) and the z-plane masks, object images, and
  drawing a room with its objects.
- `palette.cpp`: the EGA palette, the shadow palette (`_shadowPalRemap`), colour cycling.
- Player: `--room N` writes a room as a PNG.
- Check: rooms 1 and a few others as PNGs, compared against ScummVM screenshots.

### Phase 3: scripts

- `script_v5.cpp`, `script_v4.cpp`, `script_v3.cpp`: the opcode table (generated from
  `setupOpcodes`, as Maniacal does with `port_opcodes.py`), a decoder and a disassembler.
- Player: `--script N` and `--room-scripts N` disassemble.
- Check: every global and room script decodes to its end.

### Phase 4: the game loop

- `script.cpp`, `scumm.cpp`, `vars.cpp`: script slots, variables and bit variables, the boot
  script, room changes, the camera (`camera.cpp`), Loom's start-up variable values (`vars.cpp`,
  number of sounds, heap space).
- The copy protection: as ScummVM does by default, room 69 starts script 205 in place of 201
  (`script_v5.cpp`, `o5_startScript`); `--copy-protection` keeps the Book of Patterns check.
- Check: a headless run from boot reaches the title and the first room.

### Phase 5: actors and costumes

- `costume.cpp`: the classic costume format and renderer, the v3 branches.
- `actor.cpp`, `boxes.cpp`: walking, scaling, box flags (`o3_setBoxFlags`), Loom's actor palette
  case.
- Check: Bobbin walks across the first room along the boxes.

### Phase 6: text

- `charset.cpp`, `string.cpp`: the v3 charset renderer, messages and talking (Loom's talk without
  animation for empty lines).
- Check: the opening dialogue as screenshots.

### Phase 7: the distaff and input

- `verbs.cpp`, `input.cpp`, `cursor.cpp`: the verbs the scripts draw (the distaff's notes),
  clicks, Loom's cursor built from the charset, the keys (skipping cutscenes, the period for
  lines).
- `gfx.cpp`: the flashlight that lights dark rooms, with Loom v3's offset (`drawFlashlight`).
- The SDL host in the player: a window, mouse, keys.
- Check: a scripted run plays the first drafts (opening, dyeing) headless.

### Phase 8: saves

- `saveload.cpp`, `script_v4.cpp` (`o4_saveLoadGame`, Loom's save names from string 9): the
  game's own save screen and ScummVM-compatible save files.
- Check: a save written by Distaff loads in ScummVM, and the reverse.

### Phase 9: sound

- PC speaker and PCjr first, with `Player_V2` (`players/player_v2.cpp`, the v3 path).
- AdLib next, with `Player_AD` (`players/player_ad.cpp`) and an OPL2 emulator.
- MT-32 (iMUSE and the extra `8x.LFL` files) is out of scope.
- Check: the sound output of known scenes against recordings.

### Phase 10: the whole game

- Walkthrough tests that play from the opening to the ending, a section at a time, with saves at
  each section's end.

## VGA CD

- `resource_v4.cpp`: `000.LFL` and the `DISK01.LEC` bundle (XOR 0x69, rooms by offset), the
  `90x.LFL` files.
- 256-colour strip codecs and palettes (`gfx.cpp`), v4 opcode changes, Loom VGA's own text and
  interface paths (`gfx_gui.cpp`, `charset.cpp`).
- `soundcd.cpp`: the music and sound from the one CD audio track, played by start and length,
  and the subtitle timing that follows the CD position (`string.cpp`). The track is Ogg Vorbis
  here; a WAV copy is also available, which would avoid a decoder dependency.

## FM Towns

- `resource_v3.cpp` with `GF_OLD256`: 6-byte headers, files not encoded.
- `gfx_towns.cpp`: the Towns' 256-colour graphics and text layer.
- `players/player_towns.cpp` (`Player_Towns_v1`) for the effects, and the 16 CD tracks (FLAC
  here; a WAV copy is also available).
- The difficulty selection ScummVM shows in place of a boot parameter (`scumm.cpp`).
